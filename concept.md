# Концепция проекта «Управление товарными остатками»

## 1. Назначение

«Управление товарными остатками» — локальное веб-приложение для закупщика, руководителя и финансового директора торговой компании, продающей электронику. Оно принимает единую выгрузку из 1С или Google Таблиц, проводит ABC/XYZ-анализ, рассчитывает обеспеченность запасом и рекомендуемый объём заказа, заранее предупреждает о возможном дефиците и показывает товары с риском перехода в неликвид.

Приложение состоит только из трёх файлов: `index.html`, `styles.css` и `app.js`. Сервер и база данных не используются. Данные и настройки хранятся локально в браузере.

## 2. Согласованные условия

- Анализ запускается пользователем вручную по необходимости.
- Остатки всех магазинов и складов объединяются; рекомендации рассчитываются суммарно по компании.
- История продаж — от 6 до 12 месяцев, рекомендуемый период — 12 месяцев.
- Продажи для XYZ-анализа агрегируются по неделям.
- Один импортируемый файл содержит историю продаж, остатки и остальные необходимые поля.
- Основной идентификатор товара — наименование.
- ABC-анализ доступен по выручке, валовой прибыли и количеству проданных единиц.
- XYZ-анализ учитывает недели без продаж как нулевой спрос.
- Для новых товаров предусмотрен отдельный статус «Недостаточно данных».
- Срок поставки настраивается; значение по умолчанию — 5 календарных дней.
- Типичный интервал между заказами — 7 дней.
- Заказ округляется до целых единиц товара.
- Предварительное предупреждение выводится за 3 дня до предполагаемой точки заказа; период настраивается.
- Неликвид: товар есть в остатке, но продаж не было 90 дней. Порог настраивается.
- Нужны фильтры, поиск, графики выбранного товара и экспорт результатов в Excel.
- Интерфейс — русскоязычная строгая светлая бизнес-панель с визуальной сдержанностью в стиле Apple.
- Целевые браузеры: Chrome, Яндекс Браузер и Safari.
- Приложение должно содержать демонстрационный набор данных.

## 3. Принятые допущения

Фраза «пользовательская версия» в ответе о способе использования трактуется как локальная однопользовательская версия без синхронизации между компьютерами. Каждый браузер имеет отдельное хранилище. Для работы на другом компьютере пользователь заново загружает исходный файл.

Наименование принимается как ключ товара согласно требованиям, но это рискованно: различия в регистре, пробелах или написании могут создать дубли. При импорте приложение нормализует пробелы и регистр, показывает возможные дубли и просит исправить их в исходном файле. В дальнейшем желательно перейти на неизменяемый код товара из 1С.

ABC-матрица по умолчанию строится по валовой прибыли как наиболее полезному для управления ассортиментом показателю. Пользователь может переключить её на выручку или количество. Все три результата рассчитываются и доступны одновременно.

## 4. Импорт данных

### Рекомендуемый сценарий первой версии

1. Пользователь выгружает из 1С единый файл `.xlsx` или формирует его в Google Таблицах и скачивает как Excel.
2. На странице выбирает файл перетаскиванием или через диалог загрузки.
3. Приложение распознаёт колонки, показывает предварительный просмотр и результаты проверки.
4. После подтверждения предыдущий рабочий набор заменяется новым, затем выполняются расчёты.

Дополнительно стоит поддержать CSV UTF-8 с разделителями `;` и `,`. Excel является основным пользовательским форматом. Прямое чтение закрытой Google Таблицы не входит в первую версию: для него нужна OAuth-авторизация либо публикация таблицы в открытый доступ. В будущем можно добавить импорт по ссылке на опубликованный CSV.

### Формат одной строки

Рекомендуемая детализация — один товар за один день. Если 1С может выгрузить только недельные итоги, приложение также принимает одну строку на товар за неделю.

Обязательные поля:

| Поле | Назначение |
|---|---|
| `Наименование` | Идентификатор товара |
| `Дата` | Дата или начало периода продаж |
| `Количество продаж` | Продано единиц за период |
| `Выручка` | Выручка за период |
| `Валовая прибыль` | Выручка минус себестоимость продаж |
| `Остаток` | Текущий суммарный физический остаток |

Рекомендуемые поля:

| Поле | Значение по умолчанию при отсутствии |
|---|---|
| `Категория` | «Без категории» |
| `Поставщик` | «Не указан» |
| `В резерве` | 0 |
| `В пути` | 0 |
| `Срок поставки, дней` | настройка приложения, по умолчанию 5 |
| `Минимальная партия` | 1 |
| `Кратность упаковки` | 1 |
| `Закупочная цена` | не используется при отсутствии |

Если остаток повторяется в каждой строке истории, приложение берёт последнее по дате значение для товара, а не суммирует его. Остатки по разным магазинам можно суммировать до выгрузки либо передавать отдельными строками с колонкой `Магазин`; в последнем случае приложение суммирует последние остатки товара по каждой точке.

### Проверка импорта

До расчёта показываются:

- число строк, товаров и диапазон дат;
- отсутствующие обязательные поля;
- пустые и дублирующиеся наименования;
- нечисловые суммы и количества;
- отрицательные продажи или остатки;
- пропуски дат и товары с короткой историей;
- предполагаемый размер данных в локальном хранилище.

Повторная загрузка полностью заменяет текущий набор, поэтому дедупликация между импортами не требуется.

## 5. ABC-анализ

Для каждого товара за выбранный период суммируются:

- выручка;
- валовая прибыль;
- проданное количество.

Для выбранного показателя товары сортируются по убыванию вклада. Вычисляются доля товара и накопительная доля:

- A — до 80% накопительного результата;
- B — следующие 15%, то есть от 80% до 95%;
- C — оставшиеся 5%, то есть от 95% до 100%.

Границы доступны в настройках и должны проходить проверку корректности. Товар, на котором пересекается граница, включается в более высокий класс. Отрицательные продажи, возвраты, списания, подарки и внутренние перемещения исключаются из анализа и отражаются в отчёте ошибок, если исходный файл не разделяет типы операций.

Рекомендуемый вариант — считать ABC по всему ассортименту, а категорию использовать как фильтр. Дополнительный переключатель «Считать внутри категорий» позволит сравнивать товары только с аналогами, не меняя основную методику.

## 6. XYZ-анализ

Продажи каждого товара распределяются по календарным неделям. Пропущенные недели внутри выбранного периода заполняются нулевыми значениями. Рассчитываются среднее недельное количество, стандартное отклонение и коэффициент вариации:

`CV = стандартное отклонение / средний недельный спрос × 100%`.

Классы по умолчанию:

- X — CV до 10% включительно: устойчивый спрос;
- Y — CV более 10%, но не более 25%: умеренные колебания;
- Z — CV более 25%: нерегулярный спрос.

Границы настраиваются. Если средний спрос равен нулю, товар не получает класс Z автоматически: при наличии остатка он попадает в статус «Нет спроса / риск неликвида». Если истории меньше 8 полных недель, назначается статус «Недостаточно данных». Сезонность в первой версии отдельно не моделируется.

Итоговая матрица содержит девять сегментов AX–CZ и два специальных сегмента: «Недостаточно данных» и «Нет спроса».

## 7. Точка заказа и рекомендуемое количество

### Базовые величины

- `Свободный остаток = Остаток − В резерве`.
- `Позиция запаса = Свободный остаток + В пути`.
- `Средний дневной спрос = Средний недельный спрос / 7`.
- `Дни запаса = Свободный остаток / Средний дневной спрос`.

Если спрос равен нулю, дни запаса считаются неопределёнными, а не бесконечными.

### Страховой запас

Рекомендуется статистический метод, учитывающий нестабильность недельного спроса:

`Страховой запас = z × σнед × √((Срок поставки + Интервал заказа) / 7)`.

Здесь `σнед` — стандартное отклонение недельного спроса, интервал заказа по умолчанию равен 7 дням. Параметр `z` скрыт в расширенных настройках; значение по умолчанию 1,65 соответствует ориентировочному уровню сервиса 95%. Для товаров Z при недостаточной истории приложение показывает, что рекомендация имеет низкую надёжность.

### Расчёт

- `Точка заказа = Средний дневной спрос × Срок поставки + Страховой запас`.
- `Целевой запас = Средний дневной спрос × (Срок поставки + Интервал заказа) + Страховой запас`.
- `Рекомендованный заказ = max(0, Целевой запас − Позиция запаса)`.

Результат округляется вверх до целой единицы. Если в файле присутствуют минимальная партия и кратность упаковки, сначала применяется минимальная партия, затем округление вверх до кратности упаковки.

Параллельно с количественной формулой приложение сравнивает дни запаса со сроком поставки. Это делает решение понятным закупщику и позволяет заметить критический товар даже при неполных исходных данных.

## 8. Статусы и предупреждения

Приоритет статусов — сверху вниз:

1. **Нет в наличии** — свободный остаток не больше нуля, спрос положительный.
2. **Заказать сейчас** — позиция запаса достигла точки заказа либо дней свободного запаса не больше срока поставки.
3. **Заказать в ближайшее время** — дней запаса не больше срока поставки плюс 3 настраиваемых дня.
4. **Риск неликвида** — остаток положительный, последняя продажа была 90 или более дней назад.
5. **Избыточный запас** — запас превышает настраиваемый горизонт, рекомендуемое начальное значение — 90 дней, при наличии текущего спроса.
6. **Недостаточно данных** — менее 8 полных недель истории.
7. **Запас в норме** — остальные товары.

Дополнительно можно показывать мягкое предупреждение «Снижение активности» после 60 дней без продаж, чтобы не ждать порога неликвида.

## 9. Аномалии и спорные данные

Рекомендуемое поведение:

- отрицательный остаток сохраняется как проблема учёта, но для расчёта дней запаса используется 0;
- отрицательные продажи считаются возвратами и по умолчанию исключаются из спроса;
- резкие всплески не удаляются автоматически, поскольку они могут быть реальными оптовыми продажами или акциями;
- аномалией помечается неделя, где спрос значительно выше обычного; пользователь может включить настройку «Исключать аномальные недели из прогноза»;
- по умолчанию расчёт выполняется по исходным данным, а рядом отображается предупреждение о сниженной надёжности;
- товары с нулевой или отрицательной валовой прибылью выделяются отдельно и не должны искажать ABC по прибыли.

## 10. Интерфейс

### Навигация

Одностраничная панель содержит разделы:

1. **Обзор** — ключевые показатели и критические сигналы.
2. **К заказу** — приоритетный рабочий список закупщика.
3. **ABC/XYZ** — матрица сегментов и расшифровка.
4. **Неликвиды** — товары без продаж и избыточные остатки.
5. **Все товары** — полная таблица с поиском и фильтрами.
6. **Импорт** — загрузка, проверка и демонстрационные данные.
7. **Настройки** — пороги и параметры расчёта.

### Главный экран

Рекомендуемые карточки:

- товаров к немедленному заказу;
- сумма рекомендованной закупки, если есть закупочные цены;
- товаров с риском дефицита в ближайшие дни;
- товаров без остатка при наличии спроса;
- стоимость неликвидных остатков;
- число неликвидных позиций;
- оборачиваемость и среднее число дней запаса;
- дата последней загрузки и качество данных.

Ниже располагаются список самых срочных заказов, матрица ABC/XYZ, диаграмма структуры запасов по статусам и список крупнейших неликвидных остатков.

### Таблица товаров

Основные столбцы: товар, категория, поставщик, ABC по выбранной метрике, XYZ, средние продажи, свободный остаток, товар в пути, дни запаса, точка заказа, рекомендация, статус и дата последней продажи.

Предусмотрены поиск по наименованию и фильтры по категории, поставщику, классу ABC/XYZ и статусу. Сортировка по срочности заказа является начальной.

### Карточка товара

При выборе товара открывается боковая панель с:

- историей недельных продаж за 6–12 месяцев;
- линиями среднего спроса и аномальных недель;
- динамикой доступного остатка, если она есть в выгрузке;
- днями запаса, сроком поставки и точкой заказа;
- объяснением формулы рекомендации простыми словами;
- ABC-классами по трём показателям и XYZ-классом;
- историей последних продаж и признаками риска неликвида.

## 11. Экспорт

Кнопка «Экспорт в Excel» создаёт книгу с листами:

- `К заказу`;
- `ABC-XYZ`;
- `Неликвиды`;
- `Все товары`;
- `Параметры расчёта`.

В списке заказа должны быть товар, поставщик, остаток, в пути, средний спрос, срок поставки, рекомендуемое количество, ориентировочная стоимость и причина рекомендации.

## 12. Хранение и безопасность

В `localStorage` сохраняются нормализованный рабочий набор, настройки, дата импорта и состояние интерфейса. История старых импортов не сохраняется.

Важно: квота `localStorage` обычно составляет всего несколько мегабайт и различается по браузерам. Набор из 50 000 строк может не поместиться, особенно в Safari. Поэтому приложение обязано:

- оценивать размер до записи;
- сохранять только необходимые нормализованные поля, без копии исходного файла;
- перехватывать ошибку переполнения и не удалять ранее сохранённый набор;
- позволять выполнить анализ текущего файла в памяти, даже если его нельзя сохранить;
- показывать понятное предупреждение о размере.

Если реальные выгрузки регулярно превышают квоту, необходимым техническим продолжением станет IndexedDB. Это по-прежнему локальное браузерное хранилище без базы данных на сервере, однако в первую версию оно не включается согласно текущему решению.

Локальный пароль защищает вход от случайного доступа, но без сервера не является полноценной системой пользователей. Рекомендуемый вариант — шифровать сохранённый набор средствами Web Crypto на основе пароля. Пароль нигде не хранится и не восстанавливается; при его утрате данные можно вернуть только повторным импортом. После закрытия или перезагрузки страницы требуется новый вход.

## 13. Техническая реализация и ограничения

- `index.html` — структура приложения и диалоги.
- `styles.css` — адаптивная бизнес-панель, таблицы, статусы и печатные стили.
- `app.js` — импорт, проверка, расчёты, хранение, графики и экспорт.
- Для чтения/записи Excel рекомендуется SheetJS, для графиков — Chart.js.
- Чтобы приложение открывалось двойным кликом, библиотеки лучше включить непосредственно в проект либо предусмотреть понятное сообщение при отсутствии интернета. CDN проще, но делает импорт Excel и графики зависимыми от подключения.
- Основной формат экрана — настольный; на планшете сохраняется просмотр, широкие таблицы прокручиваются горизонтально.
- Браузеры проверяются на одинаковое чтение дат, кодировок CSV и работу локального хранилища.

Ограничение трёх файлов конфликтует с полностью автономным включением сторонних библиотек: локальные копии библиотек потребовали бы дополнительных файлов, а встраивание их исходного кода в `app.js` сделало бы файл чрезмерно большим. Для первой версии предлагается загрузка библиотек с CDN и сохранение структуры из трёх файлов. Без интернета приложение сможет показать ранее сохранённые результаты, но импорт/экспорт Excel и графики могут быть недоступны. Альтернатива для последующего согласования — добавить локальные файлы библиотек.

## 14. Визуальный стиль

- светлый фон, много свободного пространства и строгая типографика;
- нейтральные серые поверхности, тонкие границы и умеренное скругление;
- красный — только критический дефицит, оранжевый — раннее предупреждение, зелёный — норма, фиолетовый/серый — неликвид и отсутствие данных;
- числа выровнены и форматируются с разделителями разрядов;
- у каждого статуса есть цвет, текст и значок, чтобы смысл не зависел только от цвета;
- ключевые формулы раскрываются через подсказки «Как рассчитано».

## 16. Критерии готовности первой версии

Первая версия считается готовой, если пользователь может открыть страницу, войти по локальному паролю, загрузить один корректный файл или демоданные, увидеть отчёт проверки, выполнить анализ и получить:

- ABC по трём показателям;
- недельный XYZ и матрицу AX–CZ;
- дни запаса, точку заказа и целое рекомендуемое количество;
- статусы срочности и неликвидности;
- фильтруемую таблицу и карточку товара с графиком;
- сводный дашборд;
- Excel-файл с рекомендациями и результатами;
- сохранение доступного по квоте набора и настроек в браузере.

## 17. Решения, которые стоит подтвердить перед разработкой

Концепция позволяет начать прототипирование, но перед финальной реализацией желательно подтвердить четыре пункта:

1. Под «пользовательской версией» действительно понимается локальная работа без синхронизации между компьютерами.
2. Допустима зависимость от интернета для загрузки SheetJS и Chart.js при сохранении строгого ограничения в три файла.
3. В выгрузке можно предоставить валовую прибыль либо себестоимость, чтобы её вычислить.
4. Повторяющиеся наименования товаров будут исправляться в источнике; в перспективе будет добавлен код 1С.
