# Эксплуатация «Управления товарными остатками»

## Запуск

Для локальной проверки используйте `pnpm start` и откройте `http://localhost:3000`.

Для контейнерного запуска: `docker compose up --build -d`. Данные находятся в постоянном томе `zapasometr-data`. Перед production-развёртыванием задайте секреты SMTP и используйте защищённый HTTPS reverse proxy.

Скопируйте `.env.example` в `.env`, внесите выданные почтовым администратором значения и не добавляйте `.env` в репозиторий. Обычно используются `SMTP_PORT=587` и `SMTP_SECURE=false` (STARTTLS); для SMTPS на 465 — `SMTP_SECURE=true`. После запуска отправьте тестовый отчёт на собственный адрес из раздела «К заказу».

Первого администратора создаёт оператор: `pnpm bootstrap-admin -- email@example.ru "Имя" "длинный-временный-пароль"`.

## Проверка после развёртывания

1. Откройте `GET /api/health` — ожидается `{"ok":true}`.
2. Войдите под бизнес-пользователем, загрузите демоданные, откройте «К заказу» и выгрузите Excel.
3. Проверьте, что администратор не видит бизнес-разделы.

## Резервная копия и восстановление

Создание: `pnpm backup -- backups/перед-обновлением.db`.

Перед восстановлением остановите приложение. Затем выполните: `CONFIRM_RESTORE=yes pnpm restore-backup -- backups/перед-обновлением.db`. Команда намеренно не выполняется без явного подтверждения, поскольку перезаписывает рабочую базу.

## Ограничения перед production-приёмкой

- Реальную доставку отчётов нужно проверить с корпоративным SMTP; без конфигурации приложение сохраняет ошибку отправки и предлагает скачать файл.
- Docker CLI и корпоративный SMTP недоступны в текущей среде, поэтому их проверка остаётся операционной задачей.
